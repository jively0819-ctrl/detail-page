# 상세페이지 문안 자동화 (닥터에스떼 · 벨리닉)

공유 비밀번호로 들어가는 사내용 상세페이지 문안 자동 작성 사이트입니다.
**제품명 · 용량 · 대표성분(최대 3개) · 전성분**만 입력하면, 브랜드별 기존 상세페이지 레이아웃에 맞춰 화장품법 표현 기준을 지킨 문안을 작성하고, 직접 수정한 뒤 엑셀(배경 30% + 흰 박스 문안)로 내려받을 수 있습니다.

- 기본 비밀번호: `detail2026!` → **배포 직후 꼭 바꾸세요** (아래 4번)
- 서버, DB, 외부 AI가 필요 없습니다. GitHub Pages에 올리기만 하면 동작합니다.

---

## 1. 사용 흐름

1. 링크 접속 → 공유 비밀번호 입력
2. 브랜드 선택 (닥터에스떼 / 벨리닉)
3. 입력템플릿(.docx)을 업로드하거나 화면에 바로 입력
   - 전성분을 붙여넣으면 성분을 자동으로 분류합니다 (대표성분 후보, 기능성 고시 성분, 베이스 성분).
   - 성분 칩을 클릭하면 대표성분으로 지정됩니다 (최대 3개). 비워 두면 자동으로 추천합니다.
4. [상세페이지 문안 생성] → 기존 상세 이미지(불투명도 30%) 위에 흰 박스 문안이 배치됩니다.
5. 박스 안 글자를 클릭해서 바로 수정합니다. 오른쪽 [표현 검수]에서 위험 표현을 확인하고 대체어로 고칩니다.
6. [엑셀 다운로드] → 디자이너에게 전달합니다. 시트 1은 상세 레이아웃, 시트 2 [문안 목록]에는 전체 문안과 검수 메모가 들어갑니다.
7. 왼쪽 사이드바 히스토리에 자동으로 저장됩니다.

## 2. GitHub Pages 배포 (처음 1회, 약 5분)

1. GitHub에 로그인 → 오른쪽 위 **+** → **New repository**
   - 이름 예: `detail-page` / Public 선택 (무료 플랜 기준. 아래 보안 안내 참고)
2. 만든 저장소에서 **Add file → Upload files** → 이 폴더의 **내용 전체**(index.html, assets, js, layouts, templates, tools, .nojekyll)를 끌어다 놓고 **Commit changes**
   - `.nojekyll`이 안 보이면 숨김 파일 표시를 켜 주세요 (없어도 동작은 합니다).
3. 저장소 **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main` / `(root)` → **Save**
4. 1~2분 뒤 `https://<GitHub아이디>.github.io/detail-page/` 주소가 생깁니다. 이 링크와 비밀번호를 팀에 공유하면 됩니다.

## 3. 파일 구조

```
index.html                 화면
assets/style.css           디자인
js/config.js               비밀번호 해시, 브랜드 정보(제조업자·책임판매업자·상담번호 기본값), 글자 크기
js/ingredients.js          성분 사전 (설명 문안·카테고리·기능성 고시 성분)
js/compliance.js           화장품법 표현 검사 규칙
js/generator.js            문안 생성 엔진 (제품유형별 사용법·텍스처 포함)
js/files.js                Word 읽기 / Excel 만들기
layouts/drsthe/            닥터에스떼 상세 이미지 + 문안 위치(layout.js)
layouts/velinic/           벨리닉 상세 이미지 + 문안 위치 (현재 임시 이미지)
templates/                 간편 입력템플릿(.docx)
tools/password.html        비밀번호 해시 만들기
```

## 4. 비밀번호 바꾸기

1. 배포된 사이트의 `/tools/password.html` 에 접속 (예: `https://아이디.github.io/detail-page/tools/password.html`)
2. 새 비밀번호를 입력 → 해시 복사
3. GitHub에서 `js/config.js` 열기 → 연필(Edit) → `passwordHash: '...'` 값을 붙여넣기 → Commit

## 5. 벨리닉 상세 이미지 넣기

현재 벨리닉은 임시 배경입니다. 실제 상세 이미지를 받으면:

1. 이미지를 폭 1440px로 맞춰 `layouts/velinic/img/01.jpg, 02.jpg …` 순서로 교체(업로드)합니다.
2. `layouts/velinic/layout.js`의 `images` 목록에서 각 이미지의 높이(`h`, px)를 실제 높이로 고칩니다. 장수가 다르면 항목을 추가하거나 삭제합니다.
3. 사이트에서 벨리닉 문안을 하나 생성 → [위치 조정]을 켜고 박스를 상세 이미지의 문안 위치로 끌어 옮깁니다.
4. 오른쪽 아래 [현재 위치를 레이아웃 파일로 내보내기] → 내려받은 `layout.js`로 `layouts/velinic/layout.js`를 교체합니다.

닥터에스떼도 같은 방법으로 상세 이미지나 문안 위치를 바꿀 수 있습니다.

## 6. 성분 · 표현 규칙 추가

- 성분 설명 추가: `js/ingredients.js` 에 한 줄 추가
  `E('표준 국문명', 'INCI명', '카테고리', '헤드라인', '설명 문장', 우선순위, ['별칭'], '기능성구분');`
- 금지 · 주의 표현 추가: `js/compliance.js` 에 `add('ban' | 'func' | 'warn', '정규식', '사유', '대체어');`
- 사전에 없는 성분은 이름 규칙(○○추출물, ○○가루, ○○오일 등)으로 무난한 원료 특성 문안을 만듭니다.

## 7. 알아 둘 점

- **보안**: GitHub Pages(무료)는 공개 저장소에서만 동작하므로, 저장소 주소를 아는 사람은 코드와 상세 이미지를 볼 수 있습니다. 비밀번호는 화면 진입을 막는 수준의 보호입니다. 미공개 상세 이미지를 엄격하게 보호해야 한다면 GitHub Enterprise의 Private Pages를 쓰거나, Cloudflare Pages + Cloudflare Access(무료, 이메일 인증) 같은 접근 제어 서비스로 옮기는 것을 권장합니다.
- **히스토리**: 각자 브라우저에 저장됩니다(다른 PC와 자동 공유되지 않음). 사이드바의 [히스토리 백업 / 불러오기]로 JSON 파일을 주고받을 수 있습니다.
- **표현 검수**: 화장품법 제13조, 시행규칙 [별표5], 식약처 「화장품 표시·광고 관리 지침」의 대표 금지 표현을 기준으로 자동 검사합니다. 법률 자문을 대체하지 않으므로 최종 게시 전에 담당자(RA)가 검토해야 합니다.
- **엑셀 글꼴**: 엑셀 문안은 ‘맑은 고딕’으로 저장됩니다. 박스 높이는 여유 있게 잡지만, 문안을 많이 늘렸다면 엑셀에서 박스 크기를 조금 조정해 주세요.
- 로컬에서 `index.html`을 더블클릭해 열면 엑셀 다운로드(이미지 불러오기)가 막힐 수 있습니다. 배포된 주소에서 사용하세요.

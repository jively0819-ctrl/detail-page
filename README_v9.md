## 1. 선택 입력
- 보이는 것은 [인체적용시험 결과 보고서] · [제조사 추가 자료] 2칸뿐입니다. 파일을 끌어다 놓으면 끝납니다.
- 보고서: 효능 시험 / 피부자극 시험을 자동 구분 → 시험명 · 결론 문구(원문) · 기관 · 기간 · 대상 인원 채움
- 제조사 자료: 전성분 · 대표성분 함량 · 용량 · 사용법 · 사용기한 · 기능성/심사번호 · 특허번호 · 비건 인증 · 상담전화 · 추가 주의사항 · ※주석 문구
- 형식: PDF · Word(.docx) · 한글(.hwpx) · Excel(.xlsx) · 이미지 · 텍스트 / 스캔 PDF · 사진은 [OCR로 읽기] (처음 1회 1분 정도)
- 이미 입력한 칸은 덮어쓰지 않고 [이 값으로 바꾸기]로 선택합니다. 전성분이 입력값과 다르면 경고합니다.
- 파일이 없으면 [결론 문구 붙여넣기]로 필요한 문장만 붙여 넣어도 됩니다.
- 기존 입력칸은 [추출값 확인 · 직접 입력] 안에 그대로 있습니다. (Word 입력템플릿 업로드도 그대로 동작)
- 업로드한 파일 원본은 저장 · 동기화하지 않습니다. 채워진 값만 히스토리에 저장되고 v8 동기화로 공유됩니다.

## 2. 필수 표기 문구 (상세페이지 관련 영역 바로 아래 · 초록 점선 박스)
| 영역 | 들어가는 문구 | 조건 |
|---|---|---|
| 제품 표기 | *엑토인 1%, 판테놀 2.7% 함유 (원료 함량 기준) | 함량 입력 · 제품명에 % 있을 때 (제품명에 성분명만 있고 함량이 없으면 입력 요청) |
| 제품 표기 | *식약처 ○○ 기능성 심사(보고)를 받은 기능성 화장품 (번호) | 기능성 선택 시 |
| 성분 | *원료의 특성에 한함 · 제조사 요청 주석 | 항상 |
| 원료 · 인증 | *피토테라좀® 그레이프 : 특허 원료에 한함 (특허번호) | 벨리닉 항상 (번호 없으면 주황 박스) |
| 원료 · 인증 | *특허 원료에 한함 / *비건 인증 안내 (인증기관) | 특허번호 · 비건 자료가 있을 때 |
| 인체적용시험 | *시험명 · *시험기관·기간·대상 · *개인차 안내 | 시험 결과가 있을 때 |
| 피부자극시험 | *시험기관·기간 · *모든 사람에게 자극이 없다는 의미는 아님 · *개인차 안내 | 자극시험 결과가 있을 때 |
| 제형 이미지 | *이미지는 제품의 이해를 돕기 위한 연출 컷 | 항상 |
- 생성 문안에 같은 문구가 이미 있으면 넣지 않습니다. 법정 표기로 처리되어 표현 검수 대상에서 빠집니다.
- 편집 화면 오른쪽 맨 위 [필수 표기 점검]: 포함 / 빠짐 / 입력 필요 표시 + [상세에 추가] [문구 복사]
- 저자극 · 인체적용시험 완료 · 특허 표현이 근거 자료 없이 있거나, AHA 성분이 있으면 경고합니다.
- 문구 수정 위치: js/v9-docs.js 의 reqRules() · 박스 위치: SPEC

## 3. 상품정보제공고시
- v7 통짜 박스(문구만) 방식으로 확정. 네모 모서리 · 불투명 흰 배경으로 뒤 표 이미지를 완전히 가립니다.
- 팩(시트 · 워시오프 · 모델링 · 슬리핑) → "눈 주위를 피하여 사용할 것", 스크럽 → 알갱이 주의 문구를 자동 추가
- (입력 필요)로 남은 항목(예: 벨리닉 소비자상담 전화번호)은 [필수 표기 점검]에 표시

## 동기화(v8) 확인 순서
1. 사이트 왼쪽 아래 배지가 "동기화 연결됨"(초록)인지 확인
2. 빨강 "계정 정보 불일치" → js/v8-sync.js 의 TEAM_EMAIL이 Firebase Authentication 사용자 이메일과 같은지, 그 사용자 비밀번호가 입장 비밀번호(detail2026!)와 같은지 확인
3. 빨강 "권한 없음" → Firestore 규칙에 history · kv 컬렉션 read/write를 로그인 사용자에게 허용했는지 확인
4. 다른 브라우저(시크릿 창)로 입장 → 한쪽에서 생성한 히스토리가 다른 쪽 목록에 바로 뜨면 정상
